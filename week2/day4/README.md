## 一、理论 20min（分 2 块，自测收尾）

### 10min｜两类幻觉定义（重点，后面记录表要用）

1. **外源幻觉（External Hallucination）**
文档、召回 chunk 里**完全没有对应信息**，LLM 凭空编造事实、数字、结论。
触发场景：问文档不存在的内容；检索召回无关内容，模型顺着无关内容瞎拓展。
2. **内源幻觉（Internal Hallucination）**
检索拿到了相关 chunk，但**信息残缺、被截断、上下文断裂、缺少约束条件**，LLM 自动脑补补齐，和原文冲突。
触发场景：信息跨 chunk、一句话被切分打断、chunk 只保留部分条件。

> 
> 一句话区分：
> 外源：资料里压根没有；内源：资料有一部分，但不全，模型自己补剩下的。

### 10min｜4 类测试用例的实验逻辑

今天 4 组 case，是对照实验：
① 文档内有明确答案 → 对照组（验证 RAG 链路正常，排除基础 bug）
② 文档完全不存在该信息 → 外源幻觉主测试组
③ 答案分散在 2 个 chunk，一次 top3 召回只能拿到其中一块 → 内源幻觉高发组
④ 召回语义相近、但是无关的 chunk（向量语义匹配错了）→ 召回缺陷带来的幻觉

> 
> 核心笔记（必写）：很多幻觉根源**不是 LLM 本身爱胡说，而是分片、检索召回的缺陷**；LLM 只是在给定的残缺上下文里，尽量输出通顺文本。

✅ 理论自测（学完自己回答）

1. 文档里没有这个知识点，模型编出来，属于哪一类幻觉？
2. 原文写 “限速最高 80”，chunk 只抓到 “限速”，模型脑补成 60，属于哪一类？
3. 为什么今天不能修改 chunk_size、top_k？

#### 给你参考样例（你可以直接仿写）

以一份设备说明书 PDF 举例：
① 文档内有答案：设备的额定电压是多少？
② 文档不存在信息：这个设备支持蓝牙 5.4 吗？（文档全程没提蓝牙）
③ 跨 chunk：设备的报警条件 + 对应的处理步骤（报警条件在 chunk1，处理步骤在 chunk2，top3 大概率只召回其中一块）
④ 语义相似无关：设备散热方式是什么？（文档讲的是外壳防护，向量和散热很接近，容易被召回）

### 阶段 2：第①类测试：文档内有明确答案（15min，对照组）

目标：确认基线 RAG 本身没有崩，能正确回答，作为参照。
操作：

1. 提问文档里清晰、集中在单个 chunk 的问题
2. 记录：召回 chunk 是否包含答案，回答是否准确
3. 如果这里就大量答错：说明你的基线脚本本身有 bug（召回逻辑、prompt 写错），先修复，再往下测幻觉！

> 
> 合格表现：能精准召回，回答正确，无幻觉。

### 阶段 3：第②类测试：文档完全没有该信息（25min，外源幻觉重点）

目标：观察 LLM 能不能遵守 prompt “不知道就说不知道”
操作：

1. 提问文档从头到尾没有提到的实体、参数、功能
2. 重点观察两种表现：
   - ✅ 理想：回答 “参考资料中没有相关信息”
   - ❌ 幻觉：自己编造参数、功能、结论
3. 记录：即使召回了一些无关片段，模型编造的内容是什么

> 
> 坑：哪怕你 prompt 写了 “不知道就说不知道”，LLM 依然很容易编造，这就是外源幻觉典型现象。

### 阶段 4：第③类测试：信息分散在多个 chunk（25min，内源幻觉重点）

目标：体会分片带来的残缺上下文问题（RAG 最常见幻觉来源）
操作：

1. 先翻 PDF，找到一个完整答案被分页、被切分器拆成 2 个 chunk 的知识点
2. 提问需要**合并两块信息才能回答**的问题
3. 现象：top3 只召回其中一块 chunk，信息不全，LLM 自动补全缺失部分，和原文冲突

> 
> 例子：原文【条件 A → 触发动作 B；注意事项 C】，A 在 chunk1，C 在 chunk2；检索只召回 chunk1，模型自己编注意事项。
> 这一类非常容易被忽略：它不是完全瞎编，看起来很合理，但是和原文不一致。

### 阶段 5：第④类测试：语义相近、但是无关召回（20min，召回缺陷）

目标：理解向量检索的短板 ——**语义相似 ≠ 事实相关**
操作：

1. 找一个 query，和文档里某段文本向量接近，但事实完全无关
2. 观察：向量库召回了这段文本，LLM 基于这段无关内容回答
3. 归类：一般记外源幻觉；备注写上【向量召回误召回，语义相近事实无关】

> 
> 这直接支撑你笔记结论：幻觉来自检索缺陷，不是 LLM 单方面问题。

## 四、当日笔记模板

1. 幻觉分两类：外源（文档无信息，凭空编造）、内源（信息残缺，模型脑补）
2. 4 类测试用例作用：①对照组校验链路；②外源幻觉；③分片带来内源幻觉；④向量误召回幻觉
3. 幻觉根源：**文本分片、检索召回缺陷是重要诱因，LLM 只是在不完整上下文里生成通顺文本**
4. prompt 约束（不知道就说不知道）只能缓解幻觉，不能根除
5. 向量匹配只看语义相似度，不理解事实逻辑，会召回相似但无关内容

## 五、高频踩坑提醒

1. ❌ 不要今天改 chunk_size、overlap、top_k！一改就破坏对照实验，分不清是参数还是幻觉本身
2. ❌ 不要主观猜幻觉：判断幻觉必须**对照原文 PDF**，不是你觉得不对就是幻觉；原文没有 = 幻觉，原文有但是被改 = 幻觉
3. ❌ 记录表不要只写 “幻觉了”，一定要把**召回 chunk 摘要**写进去，定位是召回问题，还是 LLM 生成问题
4. 同一个问题，多跑 2 次：LLM 有随机性，有时候这次编、下次老实说不知道，要记录复现情况
