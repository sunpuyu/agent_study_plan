## Day1｜Embedding 原理 + 文本切分（RecursiveCharacterTextSplitter、重叠窗口）

✅ 核心目标：理解向量语义、切分规则，**产出独立切分测试脚本**

1. 理论（40min）
   - Embedding：语义向量、余弦相似度，区分「词袋匹配」vs「语义匹配」
   - RecursiveCharacterTextSplitter：分割优先级、chunk_size /chunk_overlap 的意义，重叠窗口的作用和坑（重叠太大冗余、太小断语义）
2. 动手（80min）
   - 加载一段 PDF 文本，只做切分，不向量化、不入库
   - 对照实验：固定文本，3 组参数对比
     - (chunk=200, overlap=20)
     - (chunk=500, overlap=50)
     - (chunk=1000, overlap=100)
   - 记录：哪些分片把一句话 / 一个逻辑段落切断了（这是 RAG 最常见根源问题）
3. 卡点补视频：B 站搜 RecursiveCharacterTextSplitter
📒 当日笔记要点：分片不是越小越好，优先保证**单个 chunk 语义完整**

> 
> 【可选拓展】对比 TokenTextSplitter（后面 LLM 会按 token 计数，提前感知）

## Day2｜向量库基础（Chroma 优先，FAISS 了解）+ 跑通【极简 RAG 最小闭环】

✅ 核心目标：不再只做孤立入库检索！今天直接拼出**不带 PDF、只用几段短文的最小 RAG 问答**，第一天就能看到问答效果，建立正向反馈

1. 理论（30min）
   - Chroma：持久化、元数据、相似度检索；FAISS：L2 / 内积，适合大规模，无内置持久化
   - 向量检索流程：query embedding → 向量库相似度匹配 → 返回 top-k 片段
2. 动手（90min）
   - 脚本结构：硬编码几段文本 → 切分 → embedding → Chroma 入库 → 检索 → 拼 prompt → LLM 回答
   - 先跑通这个最小问答 Demo，确认链路通
   - 单独分支代码：同样数据换到 FAISS，对比检索结果，感受两个库差异
   📒 当日笔记要点：向量库只负责召回，**不负责理解，召回错了 LLM 救不回来**

> 
> 【可选拓展】试 MMR 检索，对比普通相似度检索的多样性差异

## Day4｜RAG 幻觉专项测试，分类记录幻觉场景

✅ 核心目标：基于 Day3 基线版本，设计对照实验，结构化记录幻觉，不是随便测

1. 理论（20min）：区分两类幻觉
   - 外源幻觉：文档里完全没有信息，模型编造
   - 内源幻觉：检索拿到片段，但片段信息不全 / 截断，模型脑补补齐
2. 动手（100min），固定 top_k=3，只换问题，4 类测试用例：
① 答案明确在文档内（正例，用来确认系统正常）
② 问题信息文档完全不存在（外源幻觉高发）
③ 关键信息被切分到两个 chunk，单次检索只能拿到一半
④ 检索召回了语义相似但无关的片段
3. 输出一份实验记录表：问题、召回 chunk、模型回答、是否幻觉、幻觉类型
📒 笔记：幻觉很多时候不是 LLM 本身问题，是**分片 + 检索召回缺陷带来的**

## Day4-2｜检索参数调优实验：top-k + 相似度阈值 score_threshold

✅ 核心目标：控制变量法，只改检索参数，其余全部沿用 Day3 基线，观察召回、回答质量、幻觉的变化

1. 理论（20min）：召回率 vs 精度权衡；top-k 太小容易漏信息，top-k 太大引入噪声
2. 动手（100min）：控制变量实验
   - 固定所有其他参数，依次测试 top_k = 1, 3, 5, 8
   - 固定 top_k=3，增加 score_threshold 过滤低分向量，试阈值 0.5、0.7
   - 记录：召回片段数量、有无无关片段、回答完整性、幻觉是否增多
   📒 笔记：找到你这份测试文档相对最优的 top-k 区间，理解不存在万能 k 值，和 chunk 大小、文档密度强相关

> 
> 【可选拓展】简单加一个重排器（`bge-reranker-base`）感受召回质量提升，不强制，属于加分项
